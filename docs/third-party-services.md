# CarbCycle Tracker 第三方服务说明草案

## 2. 委托处理与共享边界

上述服务用于完成登录、数据存储、部署、条码查询、小程序承载、运维和稳定性保障。除用户主动触发、服务必要处理、合规审查或法律法规要求外，不应将用户饮食、身体和运动记录共享给无关第三方。

上线前需由运营主体确认：

- 是否签署或接受 Supabase、Vercel 等服务的数据处理条款。
- 生产数据所在国家或地区。
- 第三方日志保留期限。
- 发生第三方服务故障或数据事件时的通知流程。

## 3. Open Food Facts 使用提示

条码查询仅在用户主动扫描或输入条码时触发。接口会向 Open Food Facts 查询商品名称、品牌、图片和营养素。返回数据可能不完整、不准确或不适合中国大陆商品包装，需要在产品中保留手动修正或自定义食物入口。

摄像头扫码由 H5 在用户点击后通过浏览器能力识别条码，视频流用于本地识别，不发送给 Open Food Facts。Open Food Facts 只接收条码数字；如果摄像头、`BarcodeDetector` 或微信内核不兼容，应保留手动输入条码路径。

上线前需将请求头中的联系邮箱替换为运营主体真实邮箱，并确认符合 Open Food Facts 的 API 使用规则。

## 4. 食物图片来源提示

当前食物图片可能来自三类来源：

| 图片来源 | 使用场景 | 合规口径 / 待办 |
| --- | --- | --- |
| Open Food Facts 商品图片 | 条码查询结果返回 `image_front_url` 时展示 | 属于第三方商品图片来源，需在第三方服务说明和隐私政策中披露 |
| Unsplash 外链图片 | 内置食物兜底图、登录 / 引导视觉图 | 浏览器会直接请求第三方图片域名；正式版需确认许可和隐私政策，或改为自托管 |
| 用户填写的图片 URL | 后续自定义食物可保存外链 URL | 当前设置页创建自定义食物传 `image_url: null`；若开放输入，需要提示用户不要填写含隐私或侵权内容的 URL |

当前没有确认食物图片上传能力，也没有确认对象存储供应商。若后续支持上传，需要新增上传服务、`uploadFile` 合法域名、图片访问控制、删除方式和保留期限。

## 5. 微信小程序后台配置提示

小程序提审前需要在微信公众平台完成：

- 主体认证和类目选择。
- `web-view` 业务域名校验。
- request 合法域名配置。
- uploadFile / downloadFile 合法域名按真实功能配置。
- 隐私保护指引填写。
- 用户协议、隐私政策和个人信息收集说明页面地址配置。

域名与第三方服务对应关系：

| 配置项 | 可能涉及的服务 | 当前建议 |
| --- | --- | --- |
| 业务域名 | 微信小程序平台、Vercel / H5 托管平台 | 填写 `WEB_APP_URL` 的 HTTPS origin |
| request 合法域名 | H5 同源 API、Supabase Auth 回调相关请求、Open Food Facts 代理接口 | 若所有请求经 H5 同源 API 代理，填写 H5 / API origin 即可；不要直接暴露非必要第三方域名 |
| 图片外链域名 | Open Food Facts、Unsplash、用户填写 URL | `web-view` 内图片加载由 H5 处理；若微信审核要求或图片加载异常，优先改为同源代理或自托管 |
| uploadFile 合法域名 | 未来食物图片或身体对比照上传、对象存储 | 当前未确认原生上传能力，提审备注写“不调用 wx.uploadFile” |
| downloadFile 合法域名 | 未来服务器文件下载 | 当前 CSV 为 H5 本地生成，真机验证后备注“不调用 wx.downloadFile” |
| 合规页面 URL | H5 托管平台 | 隐私政策、用户协议、个人信息收集说明、第三方服务说明均需 HTTPS 可访问 |

正式版还需补齐每个第三方服务的公开隐私政策 / 服务条款链接、数据处理区域、日志保留期限和联系邮箱。这些内容应与隐私政策正式版保持一致。
