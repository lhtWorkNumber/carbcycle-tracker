# 用户体系与微信小程序接入方案

## 结论

不要把“获取微信账号后自动用手机号注册”作为主路径。

推荐用户体系：

1. **账号身份层**：记录用户可以用哪些方式登录或绑定，比如 Supabase 邮箱、微信小程序 `openid`、手机号。
2. **业务资料层**：继续使用当前 `User` 表保存碳循环所需资料，比如年龄、身高、体重、目标和训练日。
3. **手机号绑定层**：手机号只在用户主动授权后获取，用作可选绑定、找回账号或后续短信登录，不作为小程序首次进入的强制条件。

这样可以让 Web / PWA、微信 `web-view` 小程序、未来原生小程序共用同一套业务数据。

## 为什么不能直接拿手机号注册

微信小程序登录和手机号授权是两件事：

- 小程序登录：前端调用 `wx.login` 获取临时 `code`，服务端通过 `code2Session` 换取 `openid`、`session_key`，满足条件时可获得 `unionid`。
- 手机号授权：用户点击手机号授权按钮后，前端拿到一次性 `code`，服务端再换取手机号信息。

因此首次进入小程序时，应该先建立微信身份，而不是假设已经有手机号。手机号属于更敏感的信息，应该在用户明确点击授权、且产品确实需要时再绑定。

## 推荐登录路径

### 路径 A：当前 Web / PWA

继续使用 Supabase Auth 邮箱 Magic Link：

1. 用户输入邮箱。
2. Supabase 完成登录会话。
3. `/api/users` 根据 Supabase auth user 创建或更新业务 `User` 资料。
4. `UserIdentity` 记录一条 `SUPABASE` 身份，后续可用于账号合并和审计。

### 路径 B：微信小程序 web-view

推荐后续按这个顺序接：

1. 小程序壳启动时调用 `wx.login`。
2. 小程序把登录 `code` 发送到同源 H5 API。
3. 服务端调用微信 `code2Session`，拿到 `openid` / `unionid`。
4. 服务端查找 `UserIdentity(provider=WECHAT_MINIAPP, provider_user_id=openid)`。
5. 如果找到用户，建立 Web 会话并进入 H5。
6. 如果没找到用户，引导用户完成资料，创建业务 `User`，再写入微信身份绑定。

如果当前仍以 Supabase Auth 作为唯一会话系统，需要在正式实现前确定“微信身份如何换成 Supabase session”。可选方案：

- 使用 Supabase 支持的自定义 / 外部身份方案统一会话。
- 保留 Supabase 邮箱登录，把微信身份作为绑定能力，不直接替代登录。
- 自建服务端 session，仅微信小程序使用，Web 继续使用 Supabase。这个方案灵活，但维护成本更高。

当前项目优先建议第二种：先绑定微信身份，保留邮箱登录；等小程序流量验证后，再投入原生微信登录会话。

### 路径 C：手机号绑定

手机号只在这些场景出现：

- 用户主动点击“绑定手机号”。
- 后续要做手机号验证码登录。
- 需要客服核验、账号找回或风控提示。

绑定后在 `UserIdentity` 中保存：

- `provider = PHONE`
- `provider_user_id = +86138...` 形式的规范化手机号
- `verified_at = 授权成功时间`

不要在没有授权的情况下把手机号当作账号主键。

## 数据模型

已新增 `UserIdentity` 表，用于承载多身份绑定：

| 字段 | 用途 |
| --- | --- |
| `user_id` | 关联业务用户 |
| `provider` | `SUPABASE`、`WECHAT_MINIAPP`、`PHONE` |
| `provider_user_id` | Supabase auth id、微信 `openid` 或规范化手机号 |
| `union_id` | 微信开放平台打通后可用于跨应用识别 |
| `app_id` | 微信小程序 AppID，便于未来多小程序隔离 |
| `verified_at` | 身份确认或手机号授权时间 |
| `raw_profile_json` | 必要时保存最小化原始返回摘要，不保存敏感无关数据 |

唯一约束是 `provider + provider_user_id`，避免同一个微信 `openid` 或手机号重复绑定多个账号。

## 合规口径

上线材料建议这样写：

- 微信登录仅用于识别同一小程序用户身份。
- 摄像头仅用于用户主动扫码，不上传、不保存视频流。
- 手机号仅在用户主动点击授权后获取，用于账号绑定、登录或找回；用户可不授权手机号，除非具体功能必须使用。
- 不应承诺“自动获取微信账号或手机号”。应说明所有敏感授权均由用户主动触发。

## 后续实施清单

1. 在微信公众平台拿到真实 AppID / AppSecret，并配置为 `WECHAT_MINIAPP_APP_ID`、`WECHAT_MINIAPP_APP_SECRET`。
2. 增加小程序壳的 `wx.login` 调用，并把临时 code 传给后端。
3. 增加 `/api/auth/wechat/miniapp` 登录或绑定接口。
4. 决定微信身份是否直接换 Supabase session；如果暂不换，则先做“登录后绑定微信”。
5. 增加“绑定手机号”按钮，只在用户主动点击时调用微信手机号授权能力。
6. 增加账号合并策略：同一手机号或 `unionid` 命中旧账号时，要求用户确认后再合并。
