## 2. 小程序配置审计

- `miniapp/project.config.json` 当前 `appid` 为 `touristappid`，正式提审必须替换为真实 AppID。
- `miniapp/miniprogram/config.js` 当前 `WEB_APP_URL` 为 `https://your-domain.com`，正式提审必须替换为生产 HTTPS H5 入口。
- `miniapp/miniprogram/pages/index/index.js` 和 `pages/webview/webview.js` 已限制只打开 `WEB_APP_URL` 同源页面，避免审核或运行时通过 query 跳转到未配置域名。
- `miniapp/miniprogram/app.json` 已声明启动页和 `web-view` 页，未发现多余页面或敏感原生权限声明。
- `miniapp/project.config.json` 的 `urlCheck` 为 `true`，符合提审前验证预期。
- 小程序壳未声明原生摄像头、相册、上传或下载权限；H5 扫码会在用户主动点击后请求浏览器摄像头能力，仍需微信真机验证。

## 3. 域名配置验收口径

提审前按以下顺序验收：

1. 生产 H5 可通过 HTTPS 访问，HTTP 会跳转 HTTPS。
2. `NEXT_PUBLIC_APP_URL` 与 `miniapp/miniprogram/config.js` 的 `WEB_APP_URL` 使用同一个 origin。
3. 微信后台业务域名配置为 `WEB_APP_URL` 的 origin，并完成校验文件部署。
4. request 合法域名包含 H5 API origin；如果 API 与 H5 同源，填写同一个 origin 即可。
5. Supabase Auth Site URL / Redirect URLs 包含正式 H5 origin 和实际回调路径。
6. 隐私政策、用户协议、个人信息清单、第三方服务说明均已部署到 HTTPS URL，并能从微信内访问。

## 4. 隐私与个人信息核对

正式版必须补齐：

- 运营主体、主体类型、联系方式、通信地址、生效日期、更新日期。
- 账号注销 / 删除全部数据流程，建议设置页入口和人工邮箱兜底都准备。
- 个人信息导出、删除单条记录、撤回授权、投诉反馈处理时限。
- 第三方服务的数据处理区域、日志保留期限、隐私政策 / 服务条款链接。
- 摄像头权限用途说明：仅用户主动扫码时用于本地识别包装条码，不上传、不保存视频流；拒绝授权后仍可手动输入条码。
- 食物图片来源说明：Open Food Facts 商品图、Unsplash 外链兜底图、用户后续填写的自定义图片 URL；正式版需确认第三方许可、隐私链接和图片加载兜底。
- 自定义食物归属说明：当前代码路径已新增 `FoodItem.user_id` 和当前用户过滤，仍需完成迁移、接口权限、前端展示、跨账号隔离和测试账号回归后，才能在正式材料中承诺用户私有。
- 身体对比照说明：当前前端仅浏览器本地预览，不上传、不传 URL；API / schema 已预留 `before_photo_url`、`after_photo_url`，若后续保存 URL 或上传路径，需要同步更新隐私政策、个人信息清单、第三方服务说明、上传域名、删除方式和保留期限。
- 若后续接入食物图片上传、微信手机号、原生扫码、身体对比照上传或错误监控，需要同步更新隐私政策、个人信息清单、第三方服务说明和小程序后台隐私保护指引。

- 截图：启动页、首页、引导页、添加食物、计划 / 统计、身体或运动记录、设置页、异常兜底提示。
- 真机记录：iOS 微信、Android 微信、微信开发者工具三类验收结果。

## 6. 未解决风险

- 真实主体、AppID、正式域名、备案状态和服务类目尚未提供，无法判断是否满足微信后台硬性要求。
- Magic Link / 邮箱登录在微信内的回跳稳定性未真机验证。
- CSV 导出和条码扫描在微信内可能受浏览器能力限制，必须保留手动输入和不可用提示。
- 摄像头授权拒绝、`BarcodeDetector` 不可用、Open Food Facts 无结果三类路径仍需真机截图和验收记录。
- 食物图片当前依赖第三方外链，可能受网络、许可或微信内加载策略影响；正式版需决定继续外链、同源代理或自托管。
- 自定义食物用户归属改动仍是待验收项；若迁移未执行、接口过滤失效或旧数据未补归属，仍可能出现跨账号可见风险。
- 身体对比照 UI 当前仅本地预览但未保存，API 又已预留 URL 字段，可能造成用户误解；需由前端 worker 明确提示或完成上传能力后再补合规。
- 设置页是否已上线协议、隐私、反馈、导出、注销 / 删除数据入口需由前端 worker 完成后再回归。
- 第三方服务的数据区域、日志保留、DPA / 服务条款接受情况仍需运营主体确认。
